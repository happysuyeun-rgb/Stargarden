## 2. 🔴 우선 수정 — 핵심 루프가 깨지는 버그 (재현 완료)

### 2-1. 일일 씨앗이 첫날 이후 다시 지급되지 않음

- **위치**: `src/stores/seedsStore.ts`, `src/features/garden/GardenPage.tsx` 125~132행
- **원인**: `hasReceivedToday`가 날짜 정보 없는 boolean이라 한 번 `true`가 되면 다음 날에도 초기화되지 않음. `GardenPage`는 `!hasReceivedToday`일 때만 씨앗을 주므로 2일차부터 씨앗이 안 나옴
- **재현 결과**: 1일차 수령 후 `hasReceivedToday = true`, 스토어에 수령 날짜를 저장하는 값이 없음 → 2일차 자동 지급 안 됨
- **개발자 모드에서 안 보이는 이유**: `SplashPage`가 진입할 때마다 `seedDevSession()`으로 값을 리셋하기 때문
- **수정 방향**: `lastReceivedDate`(KST `YYYY-MM-DD`)를 저장하고 `getKSTDateString()`과 비교해 판단. `hasReceivedToday`는 이 비교 결과로 계산

### 2-2. 깨어남 모달을 닫지 않고 새로고침하면 정원이 영구히 잠듦

- **위치**: `src/features/garden/GardenPage.tsx` 88~99행
- **원인**: 첫 진입에서 잠듦을 적용한 직후 `touchActive()`가 `lastActiveAt`을 지금으로 갱신함. 모달을 확인하지 않고 새로고침하면 `wasLongAbsent`가 `false`가 되어 두 분기 모두 해당하지 않음 → 모달이 다시 안 뜨고 `isGardenSleeping`은 계속 `true`
- **재현 결과**: 31일 만에 접속 시 모달 표시 `true` → 새로고침 후 `false`, 식물 `isSleeping = true`, 물주기 불가, 이후 몇 번을 들어와도 모달 `false`
- **수정 방향**: `isGardenSleeping`이 `true`이면 `wasLongAbsent`와 상관없이 항상 깨어남 모달을 표시

## 3. 🟡 Supabase 연동 전에 수정

### 3-1. 깨어난 뒤 잠든 시간이 성장에 한꺼번에 반영됨

- **위치**: `src/stores/gardenStore.ts` `applyGardenSleep`, `src/lib/growth.ts`
- **원인**: 깨울 때 `sleptAt`만 `null`로 지우고 `plantedAt`은 그대로 둠. 이후 계산이 `now - plantedAt`이라 잠든 기간이 그대로 더해짐
- **재현 결과**: 심은 지 10시간, 잠든 채 40시간 경과 → 진행률 0.21 / 깨운 직후 같은 시점 → 1.04 (즉시 개화)
- **수정 방향**: 깨울 때 `plantedAt`을 잠든 시간(`now - sleptAt`)만큼 뒤로 미루거나, 누적 잠듦 시간 필드를 두고 계산에서 빼기. 서버 `wake-garden`도 같은 방식으로 구현
- **기획 확인 필요**: 지금은 잠듦 판정 시점(복귀한 순간)부터만 동결됨. 30일 공백 동안에는 식물이 계속 자라므로(최대 96시간) 복귀 시 대부분 이미 개화 상태임. 의도한 정책인지 확인 필요

### 3-2. 서버 전환 경로가 아직 연결되지 않음

- `invokeEdgeFunction()`과 `isServerGardenEnabled()`를 호출하는 곳이 없음 → `VITE_USE_SERVER_GARDEN=true`로 바꿔도 아무것도 달라지지 않음
- 로그인 버튼 3개는 OAuth 없이 바로 `/onboarding`으로 이동함
- Edge Function 14종은 모두 501 스텁
- 목업 단계로는 정상이지만, **007은 Edge Function 구현 전에 운영 DB에 적용하지 말 것**. 007이 클라이언트 쓰기를 막기 때문에, 함수가 없으면 정원 데이터를 쓸 경로가 없어짐

### 3-3. `send-push`가 CRON_SECRET 값을 비교하지 않음

- **위치**: `supabase/functions/send-push/index.ts` 5~11행
- 헤더가 있는지만 확인함 → 아무 값이나 넣으면 통과. 지금은 501 스텁이라 영향이 없지만, 구현할 때 `Deno.env.get('CRON_SECRET')`과 값 비교를 반드시 넣어야 함

### 3-4. 온보딩 입력 검증 누락

- **위치**: `src/features/auth/OnboardingPage.tsx`
- 2단계에서 "시간을 몰라요"를 체크하지 않고 시진도 고르지 않아도 진행됨 → `birthTimeUnknown=false`, `birthTime=null`인 모순 데이터가 저장됨
- 만 14세 미만 가입 차단이 없음 (기능정의서 NFR-04)
- 날짜 상한이 `toISOString()`(UTC) 기준이라 KST 00~09시에는 오늘 날짜를 고를 수 없음

### 3-5. 라우트 가드 없음

- **위치**: `src/routes/index.tsx`
- `/garden`을 주소창에 직접 입력하면 로그인·온보딩 없이 정원에 들어감 (`ohangType = null` 상태)

### 3-6. 웰컴 씨앗이 항상 새싹풀(木)

- **위치**: `src/stores/seedsStore.ts` `grantWelcomeSeed`
- 설계는 "본인 오행에 맞는 일반 씨앗 1종 랜덤"인데 `SEED_IDS.woodNormal1`로 고정돼 있음

### 3-7. DB 보조 제약 부족

- 같은 `user_seed_id`로 두 슬롯에 심는 것이 DB에서 허용됨 (테스트로 확인) → `plants.user_seed_id`에 unique 제약 추가 권장
- `slot_index`(음수 허용), `garden_slots`(99 허용)에 범위 CHECK가 없음. Edge Function에서 검증하더라도 DB에 마지막 안전장치를 두는 편이 안전함
- `push_tokens.device_id`가 아직 nullable이라 같은 유저의 NULL 행이 여러 개 생김 (테스트로 확인). 클라이언트 토큰 등록을 붙이기 전에 NOT NULL 전환 필요

### 3-8. 오늘의 에너지 계산이 KST 기준이 아님

- **위치**: `src/constants/seeds.ts` `getTodayEnergy`
- 기기 시간대의 요일(`getDay()`)을 쓰고 있어 해외 사용자는 날짜가 어긋남. 매핑도 水·木이 주 2회, 나머지는 1회라 분포가 치우침. 스텁이지만 2-1을 KST로 고치면 기준이 서로 달라짐
